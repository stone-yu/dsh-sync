# DSH备份与同步

把 DSH 的内容备份到 NAS 的 WebDAV 目录，支持多台机器之间共享与还原。入口在左侧边栏脚部、设置按钮旁边。

## 入口与导航

侧边栏图标栏里有一个 **备份与同步**（和 Plugins / 日程 / 记忆 并列）。点它，中间主区域整片切换成这个面板。

面板顶部是标题 **DSH备份与同步**，下面三个页签：

| 页签 | 内容 |
| --- | --- |
| **首页** | 连接摘要、每项的本地/远端/待上传/状态，单行执行按钮，以及「刷新比对」「按方向全部执行」 |
| **同步内容配置** | 每项的开关、方向、目录列表（记忆与其他文件目录可编辑路径与远端位置），底部「保存修改」 |
| **连接配置** | WebDAV 地址、用户名、密码、远端子目录、设备名称、pull 来源/覆盖策略、冲突策略、单文件上限，底部「保存连接」 |

配置全部在页面内完成，没有弹窗。

### 设备名称

远端 `machines/` 下的目录名，默认自动生成（主机名 + 安装标识），可以改成你自己认得出的纯英文名，例如 `macbook-office`、`imac-study`。

- 只允许英文字母、数字、点、下划线、短横线，且以字母或数字开头，最长 63 字符
- 保存时统一转小写作为目录名
- **改名不会迁移旧目录**：改了之后远端会出现一个新目录，旧目录里的历史备份需要你手工移动或删除

**同步内容**：每项一个多行条目——

```
基础配置                                        待上传 · 远端还没有该项内容   [上传]
Profile 补丁层、入口表、桌面偏好与语言。
方向 [上传备份 ▾]   本地 4 个 / 6.0 KB   远端 0 个   待上传 4 个
```

第一行是开关、名称、**远端目录**、状态与操作按钮；第二行是这一项包含什么的说明；第三行是方向选择与三个比对数字。

远端目录只给「内容项」这一段（如 `baseConfig/`），不带 `machines/<本机槽位>/` 或 `shared/` 前缀，也不含 WebDAV 主机地址——槽位和远端子目录在连接摘要里已经给过，方向列也已经说明写往哪里。

**开关与方向是两个维度**：左侧开关决定「参不参与」，右侧方向决定「怎么同步」。关掉开关时方向仍被记住，重新打开即恢复原方向。

按钮文字随该行方向变化，避免「所有按钮都叫同步」的歧义：`上传` / `下载` / `对账同步`，方向为关闭时按钮禁用并显示「已关闭」。

**批量操作**：刷新比对、按方向全部执行。

## 方向是内容维度的

没有「全局同步方向」。每个内容项自己决定方向，一次运行会按方向分组执行：上传组写本机槽位、下载组读远端、双向组与共享区对账。因此可以同时做到「配置和技能双向同步，但凭据完全不动」。

不是所有方向对每一项都合法：模型配置、MCP、已安装插件、工作区索引、Agent 预设、快照、Provider 状态、日志是**从实时服务导出或含本机绝对路径**的产物，只允许 关闭 / 上传备份 / 下载还原，选不了双向。后端会拒绝非法组合并说明原因。

## 四个方向

| 方向 | 用途 | 写入行为 |
| --- | --- | --- |
| `off` | 不参与任何同步（由该行开关关闭产生）| 无 |
| `push` | 纯备份，本机是唯一写入方 | 只上传到 `machines/<本机>/` |
| `pull` | 新机器初始化、或从备份还原 | 只下载到本机 |
| `two-way` | 多台机器共享同一份数据 | 上传到 `shared/`，也从中下载 |

`push` 从不改写远端、从不删除。`pull` 从不上传。只有 `two-way` 双向写入，也只有它需要处理冲突。

## 远端布局

```
<你的 WebDAV 目录>/<remoteDir>/
  machines/<machine>/           # push 的每机独立槽位，互不覆盖
    baseConfig/dsh/…
    sessions/dsh/…
    .dsh-nas-sync/manifest.json
  shared/                       # two-way 的共用区
    baseConfig/dsh/…
    .dsh-nas-sync/base-<machine>.json   # 每台机器各自的同步基线
    baseConfig/dsh/…conflict-<machine>-<时间戳>   # 冲突副本
```

路径中的 `dsh` / `agents` / `home` / `abs` 是**根标记**，记录文件来自哪个本地根目录。正因为它被显式记下来，`pull` 才能把远端路径还原成正确的绝对路径。

`<machine>` 由主机名与 `.anonymous-user-id` 前 12 位拼成。

## 冲突是怎么判定的

双向同步的关键是基线：`base-<machine>.json` 记录"这台机器上次同步后每个文件的 sha256"。有了它才能区分三种情况：

| 本地 | 远端 | 判定 |
| --- | --- | --- |
| 等于基线 | 变了 | 只有别人改了 → 下载 |
| 变了 | 等于基线 | 只有我改了 → 上传 |
| 变了 | 变了 | 双方都改了 → 冲突 |
| 没有基线 | 两端内容不同 | 无法判断 → 冲突 |

冲突策略 `conflict`：

- `both`（默认）：本地那份**另存**为 `<文件>.conflict-<时间戳>` 并上传一份到远端，然后本地取远端版本。两边内容都不会丢。
- `newer`：按修改时间取较新的一份。
- `local` / `remote`：固定保一侧。

**不做文本合并。** 配置文件、JSON、二进制都不做行级三方合并——对这类数据自动合并的出错方式比冲突副本更糟。冲突副本是"两者都保留"，不是"合并成一个"。

**不做删除传播。** 任何一侧删掉的文件，另一侧保留，只在报告里注明。这是唯一不会丢数据的选择。

## 同步内容项

共 8 项，界面上一项一行：

| key | 名称 | 支持方向 |
| --- | --- | --- |
| `baseConfig` | 基础配置 | 上传 / 下载 / 双向 |
| `modelConfig` | 模型配置 | 上传 / 下载 |
| `mcpServers` | MCP 服务器 | 上传 / 下载 |
| `pluginInventory` | 已安装插件 | 上传 / 下载 |
| `skills` | 技能 | 上传 / 下载 / 双向 |
| `credentials` | API 密钥与令牌 | 上传 / 下载 / 双向 |
| `memory` | 记忆（可配置路径）| 上传 / 下载 / 双向 |
| `extraPaths` | 其他文件目录（可配置路径与远端位置）| 上传 / 下载 / 双向 |

只允许上传/下载的那 4 项（模型配置、MCP、插件清单、以及已移除项的历史），因为它们是**从实时服务导出的产物**或**含本机绝对路径**，双向覆盖会出错。

已按你的选择移除：`providerState`、`logs`、`pluginState`、`presets`、`recovery`，以及整组「会话数据」（`sessions`、`attachments`、`workspaceRegistry`）。

### 记忆的路径

`memory` 这一行带一个目录编辑区，和「其他文件目录」用法相同：

- **列表留空** → 自动在 `DSH_HOME` 下按 `mnemon` / `memory` 命名探测
- **填入路径** → 只用你填的，例如 mnemon 的自定义 `dataDir`

留空探测不到时，运行报告会明确提示；这时把实际目录填进来即可。

### 其他文件目录

一项由你自己填路径的同步范围：任意目录或单个文件都行，例如项目笔记、导出结果、外部盘上的资料。

**每条路径可以单独指定远端位置**，因为这类内容常常不是 DSH 私有数据，而是别的场景也要读的公共产出物。

| 远端路径 | 落点 |
| --- | --- |
| 留空 | 写进本机槽位：`machines/<本机槽位>/extraPaths/<根标记>/…` |
| 填了（如 `sata1-xxx/ai-public/out`）| 直接写到 WebDAV 根下的该位置，**不经过机器槽位** |

- 远端路径相对 **WebDAV 根目录**，不是相对远端子目录
- 不允许 `..`、`.` 或以 `http:` 之类的协议开头（防止写到预期之外的位置）
- 同一份内容可以配两条：一条留空进备份、一条指向公共位置

规则：

- 路径支持 `~` 表示用户主目录，相对路径按用户主目录解析
- 最多 50 个；重复项自动去掉
- 目录内的文件会递归收集
- 不存在的路径不会让同步失败，只在运行报告里计入「来源不存在」
- **带远端路径的条目只上传、不下载、不参与双向对账**——它们没有反向映射回本地路径的规则，把它当成「单向导出」更安全

只允许上传/下载的那 5 项，是因为它们是**从实时服务导出的产物**或**含本机绝对路径**，双向覆盖会出错。




## 新机器初始化

1. 在已有数据的机器上把要共享的内容设为 `push` 或 `two-way`，跑一次「全部同步」。
2. 在新机器上填同一个 WebDAV 地址，把要还原的内容方向改成 `下载还原`。
3. `pullFrom` 留空则读共享区；填某台机器的槽位名（如 `mbp-xxx-abcdef123456`）则直接读那台机器的备份槽。
4. `overwrite` 设为 `missing`（默认）只补缺失文件，适合新机器；`always` 用于强制覆盖还原。

## 用法

- **页面**：按方向全部执行 / 单行执行，方向来自每行自己的设置。
- **Agent**：`nas_sync` 传 `action: "plan"` 预演、`action: "run"` 执行；`items` 限定范围，`mode` 可临时覆盖所有项的方向。

## 必须知道的限制

1. **明文凭据可选但危险**。「API 密钥与令牌」默认关闭；一旦开启，`.credentials.yaml` 以未加密形式存放在 NAS，任何能读取该目录的人都能直接使用其中全部账号令牌。使用 `http://` 的 WebDAV 时链路同样是明文，报告会就此警告。双向模式下该文件还会被其他机器覆盖。
2. **`link:` / `file:` 依赖不重映射**。profile 的 `package.json` 若含本机绝对路径，`pull` 之后仍需手工修正。
3. **记忆目录留空才靠探测**。留空时插件在 `DSH_HOME` 下按 `mnemon` / `memory` 命名匹配目录；Mnemon 若配置了自定义 `dataDir`，在设置页「记忆」那一行填入该路径即可，不必依赖探测。
4. **Agent 预设导出是尽力而为**，单项读取失败会记为错误而不是中断整次同步。
5. **单文件体积上限**默认 200 MB，超出跳过并列入报告。
6. **`pull` 会写入真实路径**。它按根标记还原绝对路径，没有沙箱。真正跑 `pull` 之前先用 `plan` 预演，确认远端内容是你想要的。
